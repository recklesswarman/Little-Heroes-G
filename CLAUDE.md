# Project Conventions & Deployment Life-Cycle

## PR, CI & Multi-Deployment Workflow

- **Branch Check & PR Completion**: After making or pushing updates:
  - Check for open branches (`git branch -a`, `git fetch --prune origin`).
  - If a feature/fix branch or PR exists, verify CI checks pass (`ci.yml`: lint, test, build).
  - Complete the pull request and merge into `main`.
  - Always clean up merged branches.
- **One Canonical Link & Deployment Verification**:
  - The whole app is served from one canonical URL: **Firebase App Hosting** (`littleheroes-g1` → `https://littleheroes-g1--little-heroes-quest-8842.us-east4.hosted.app`, auto-deployed from `main`; manual rollout: `npx firebase apphosting:rollouts:create littleheroes-g1 --git-branch main --force`).
  - Retired static hosts publish lightweight redirects (`redirect/`) to the canonical App Hosting link (preserving path, query, and hash, and unregistering old Service Workers):
    1. **GitHub Pages** (`https://recklesswarman.github.io/Little-Heroes-G/`): Deployed via `.github/workflows/deploy.yml` (publishes `./redirect`).
    2. **Classic Firebase Hosting** (`https://little-heroes-quest-8842.web.app`): Deployed via `.github/workflows/firebase-hosting-deploy.yml` (publishes `./redirect` + 301 `hosting.redirects` in `firebase.json`; preserves `/api/rex/**` and `/api/gemini/**` rewrites).
  - **Family Raspberry Pi**: Stays a back-end (voice relay, Pi-hole, meals, weekly report, calendar prep) deployed via `.github/workflows/deploy-pi.yml`; the Fridge Display kiosk (`scripts/pi/fridge-display.sh`) opens the canonical App Hosting URL.
  - Confirm GitHub Actions deploy workflows finish successfully against the merge commit before concluding the task.
- **Standalone Python microservice (manual deploy, not in this checklist)**:
  `little-heroes-agy-service/` (AI companion agents, Cloud Run service
  `little-heroes-rex-agy`) is deployed manually (`gcloud run deploy`, see its
  own README) -- there is no CI automation for it, and "Deploy Everywhere" above
  doesn't cover it. The client calls `/api/rex/*` on the app's own server
  (`rexUrl()` in `src/services/serverApi.js`), and `server.js` relays it to Cloud Run
  server-side (`server/rexAgyRelay.js`, `AGY_REX_SERVICE_URL` to override), so it works
  on the Pi, App Hosting and both static sites. `VITE_AGY_REX_URL` is for local dev only. Voice narration
  is handled entirely on the client via the Web Speech API.

## Cache Sync, Store Migrations & Multi-Host Base Path

- **Service Worker via vite-plugin-pwa (no manual cache bumping)**: The PWA
  service worker is generated by `vite-plugin-pwa` (Workbox `generateSW`,
  configured in `vite.config.js`) and registered from
  `src/pwa/registerServiceWorker.js`. Don't hand-edit or re-add `public/sw.js`,
  and don't bump a `CACHE_NAME`: the precache manifest is content-hashed, so any
  changed file ships a new worker, which deletes outdated caches
  (`cleanupOutdatedCaches`), activates immediately (`skipWaiting` +
  `clientsClaim`) and reloads open tabs (`registerType: 'autoUpdate'`).
  `APP_BUILD_VERSION` in `index.html` is stamped at build time from
  `%VITE_APP_BUILD_VERSION%` (package version + git commit, see
  `computeBuildVersion` in `vite.config.js`). Keep the defensive diagnostic
  prompt if the initial app mount placeholder stays stuck for more than 3.5 seconds.
  Big media in `public/` is runtime-cached on first use rather than precached.
- **Non-Destructive Catalog & Store Merging**: Never guard catalog
  synchronization behind a one-time boolean flag in `localStorage` that
  prevents future items from appearing on existing devices. Always perform
  reconciliation in `store.init()` by iterating:
  `CATALOG.forEach(item => { if (!store.items.some(i => i.id === item.id)) store.items.push(item); });`
- **Multi-Host Adaptive Base Path**: `vite.config.js` must account for the
  execution context:
  `base: process.env.VITE_BASE_PATH || (process.env.GITHUB_ACTIONS === 'true' ? '/Little-Heroes-G/' : '/')`.
  `firebase.json` headers must disallow caching for HTML and JSON
  (`no-cache, no-store, must-revalidate`) while caching immutable versioned
  assets (`public, max-age=31536000, immutable`).

## Testing & Verification

- The regression suite lives in `scratch/` and is driven by `scratch/run_all_tests.js` (`node scratch/run_all_tests.js`). Register any new `verify_*.js`/`test_*.cjs` test file added there.
- `scratch/setup_mock_env.js` provides a mock DOM/`document`/`localStorage` for running view-rendering tests under plain Node.
- Always run `npm run build` to verify zero bundling or syntax errors prior to pushing.
